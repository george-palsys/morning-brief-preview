→ 產品頁

    • 行為變更（COVDOCS-2339）：Coverity 用戶端程式不再安裝內建的 ca-certs.pem，公開 CA 憑證改取自作業系統信任憑證庫（Java 程式用 Java cacerts）；私有 CA 需用 --certs 選項或 Connection 頁指定；搜尋順序為 COVERITY_SSL_CERT_FILE、SSL_CERT_FILE、作業系統信任憑證庫，都找不到時會出現警告。
    • 修正：CMPCPP-15868（Clang asm 搭配 typeof 的擷取問題，2025.12.0 回報）。
    • 其他（COVDOCS-2323）：Kotlin 分析改用 Sigma 分析引擎，文件已更新。
    • 支援政策：基礎版本發行 18 個月後停止支援；檔名與目錄名僅支援 ASCII。
    • 移除與棄用：除內建 ca-certs.pem 外未提及。
  • 對我們的影響：連到 Coverity Connect 的憑證是客戶內部 CA 簽發的環境，升到 2026.9.1 之後用戶端不會再帶 ca-certs.pem，要改用 --certs 或 COVERITY_SSL_CERT_FILE 指定，否則 cov-commit-defects 這類連線指令可能驗不過憑證。金融業與公部門客戶多半是內部 CA，升級前先在 lab 驗證一次；這一點是依 release notes 的說明推論，尚未實機驗證。

CI/CD/GitLab：GitLab 19.6 月度版發布，Rapid Diffs 正式取代舊的 diff 檢視，GitLab Runner 19.6 同步發布

2026-11-19

→ 產品頁

  • 類別：新版本
  • 內容：
    • 版號與發布日：GitLab 19.6，頁面寫「On November 19, 2026, GitLab 19.6 was released」。
    • CI/CD：新增 pipeline 變數的可設定上限。Self-Managed 與 Dedicated 預設不啟用；GitLab.com 為每個 pipeline 1,200 個變數、每個值 128 KiB、file 類型的值 1 MiB。
    • GitLab Runner 19.6：[runners.artifact] 新增 direct_download 設定，取代已棄用的 FF_USE_DIRECT_DOWNLOAD；新增 Ubuntu 26.04 原生套件；可選用 HTTP/2（allow_http2）；Kubernetes executor 的 pause pod 改善。
    • 行為改變（Runner）：FF_CONCRETE 的 job 現在會使用設定的 shell，shell 設為 sh 卻用到 bash 專用語法的 job 可能失敗。
    • 行為改變（平台）：Rapid Diffs GA 並取代 classic diff view；triggers 改名為 automations；Service Desk tickets 改為 work item type。
    • 安全相關：Linux 套件內建的 NGINX 由 1.31.4 升到 1.31.7，修正 CVE-2026-15176、CVE-2026-93479、CVE-2026-95101、CVE-2026-97629、CVE-2026-97205。有自訂 NGINX 設定的環境可能受影響：zero-size buffer 設定會被拒絕；IP 位址的憑證驗證只比對 IP SAN。
    • 其他主要功能：MCP server 工具呼叫的 audit events；管控 GitLab MCP server 工具（beta）；Duo Agentic Chat 的 /goal 指令與 web search（預設關閉）；workspace subagents GA；scheduled automations（beta）；Advanced SAST 支援 Rust；阻擋加入惡意套件的 MR；Business Logic Security Analyzer 可用於 Self-Managed 與 Dedicated；Workspaces 支援 ARM64。
    • 棄用與移除：release notes 要使用者升級前先讀 19.6 的 upgrade notes 與 deprecations and removals 頁；這兩頁這次沒有打開，逐項內容未確認。
  • 對我們的影響：自管 GitLab 的客戶升級前要讀 19.6 的 upgrade notes 與 deprecations 頁，這兩頁我這次沒有打開。內建 NGINX 升到 1.31.7，但 F5 這週公布的 NGINX2Root 影響範圍到 1.31.8、修正版是 1.31.9，所以 19.6 內建的 NGINX 仍在受影響範圍內；GitLab 對 NGINX2Root 的官方說明我沒有查到。Runner 的 FF_CONCRETE 行為改變可能讓 shell 設成 sh 的 job 失敗。

OpenShift：Red Hat 發布 RHSB-2026-019：nginx HTTP/2、HTTP/3 堆積溢位等 5 個漏洞（NGINX2Root），評為 Critical，已有公開 PoC，修補尚未釋出

2026-11-19

→ 產品頁

  • 類別：安全公告
  • 內容：
    • CVE：CVE-2026-123007、CVE-2026-123634、CVE-2026-123633、CVE-2026-121810、CVE-2026-113425。
    • 嚴重度：公告整體評為 Critical（各 CVE 為 Critical 或 Important）；五個 CVE 的 CVSS 3.1 基礎分數皆為 8.1（Red Hat 評分）。
    • 影響：遠端未驗證攻擊者送出特製 HTTP/2 或 HTTP/3 請求，可造成堆積溢位或 use-after-free，可能導致遠端程式碼執行或服務中斷。
    • 受影響版本：RHEL 8、9、10 的 nginx 套件，以及 Red Hat 3scale API Management Platform 2；OpenShift 等使用 RHEL nginx 的上層產品可能受影響。
    • 修正版本：尚未列出 errata，Red Hat 表示正在加速釋出修補。
    • 緩解措施：停用 HTTP/2（移除 listen 的 http2 或設定 http2 off；，對應 CVE-2026-123007、123633）；停用 HTTP/3（http3 off；，對應 CVE-2026-121810，僅 RHEL 9 的 nginx 1.26 stream 與 RHEL 10 受影響）；避免 resolver 搭配 SSI 或 mirror 的代理設定（CVE-2026-123634）；移除 mail{} 代理設定（CVE-2026-113425）。Red Hat 另提供 Ansible 修補腳本。
    • 利用狀態：PoC 已公開；公告未說明是否已有實際攻擊。
    • 日期說明：清單頁顯示公開日 2026-11-18，公告內頁顯示 Public Date 與 Updated 皆為 2026-11-19 06:49；狀態 Ongoing。
    • 補充（跨廠商的最新狀況，原本排在 CVE 段，因為有原廠產品公告所以併到這裡；含第三方媒體與其他廠商來源）：
      • 發生什麼事：F5 在 2026-11-18 發布例行週期外的安全通知，nginx 部分共 10 個 CVE，其中 5 個由資安公司 Xint 命名為「NGINX2Root」，未登入的攻擊者可能讓 worker process 當掉，在 ASLR 被關閉或被繞過時可用 worker process 的權限執行程式碼。Red Hat 在 2026-11-19 發布 RHSB-2026-019。
      • 受影響產品與版本：
        • CVE-2026-123007：HTTP/2 flow control 記憶體損毀，nginx 1.9.5 到 1.31.8，只要接受 HTTP/2 連線就受影響。
        • CVE-2026-123633：HTTP/2 的 use-after-free，nginx 1.19.7 到 1.31.8，條件是使用 HTTP/2 並把請求轉給上游。F5 列出的受影響產品除了 NGINX Plus、NGINX Open Source，還有 NGINX Instance Manager、F5 WAF for NGINX、NGINX App Protect WAF、F5 DoS for NGINX、NGINX App Protect DoS、NGINX Gateway Fabric、NGINX Ingress Controller。
        • CVE-2026-123634：resolver 的 use-after-free，nginx 0.6.18 到 1.31.8。
        • CVE-2026-121810：HTTP/3 的 use-after-free，nginx 1.25.0 到 1.31.8。
        • CVE-2026-113425：mail proxy 模組的 use-after-free，nginx 0.5.33 到 1.31.8。
        • CVE-2026-118899：TLS 1.3 讀取 request body 時的無窮迴圈，nginx 1.13.0 到 1.31.8。F5 列出的受影響產品與 CVE-2026-123633 相同，同樣包含 NGINX Gateway Fabric 與 NGINX Ingress Controller。

Confluent Platform：CONFSA-2026-37：OpenJDK「Java4Shell」（CVE-2026-114938）影響 Confluent Platform，CP 映像檔尚無修補版，先加 JVM 參數緩解

→ 產品頁

  • 類別：安全公告
  • 內容：
    • CVE 編號：CVE-2026-114938（OpenJDK，俗稱 Java4Shell）。
    • 嚴重度與 CVSS：Confluent 公告沒有寫嚴重度或 CVSS 分數，未查到。公告說明可能造成遠端程式碼執行，細節已公開。
    • 受影響條件：Java 17、21、25，執行在支援 AVX-512 VBMI 的 x86-64 處理器（Intel Ice Lake 以後、AMD Zen 4 以後）。
    • 受影響版本（套件或壓縮檔安裝，使用自備的 Java）：Confluent Platform 7.6.x 到 8.4.x、Control Center 2.0.x 到 2.7.x，搭配 OpenJDK 17.0.6 到 17.0.21.1 之前、21 到 21.0.13.1 之前、25 到 25.0.5.1 之前。修補方式是把 JDK 升到 17.0.21.1、21.0.13.1、25.0.5.1。
    • Docker 映像檔尚無修補版（公告寫 Not yet released）：Confluent Platform 映像檔 7.6.15、7.7.13、7.8.12、7.9.11、8.0.9、8.1.7、8.2.5、8.3.3、8.4.1 及更早；Control Center 2.0.0、2.1.0、2.2.2、2.3.2、2.4.2、2.5.1、2.6.1、2.7.0 及更早；Gateway 1.0.0、1.2.2、1.3.1、1.4.0 及更早。
    • 已有修補版的元件：CMF 2.0.6、2.1.6、2.2.4、2.3.4、2.4.5、2.5.1；CP for Apache Flink 1.19.3-cp8、1.20.5-cp4、2.0.2-cp5、2.1.3-cp4、2.2.0-cp4、2.3.0-cp2；Flink SQL 映像檔 2.3-cmf2.5-cp2；Flink Kubernetes Operator 1.12.1-cp4、1.13.0-cp7、1.14.0-cp5、1.15.0-cp5、1.16.1-cp2；CFK init container 2.10.3、2.11.3、3.0.1。
    • 暫時緩解：在每個受影響的 Java 17、21、25 程序加上 -XX:-UseBASE64Intrinsics 並重啟（Java 8 不要加，程序會無法啟動）；用 jinfo -flag UseBASE64Intrinsics <pid> 確認。設定位置：KAFKA_OPTS、SCHEMA_REGISTRY_OPTS、KAFKAREST_OPTS、KSQL_OPTS、CONTROL_CENTER_OPTS、GATEWAY_OPTS；CFK 用 spec.configOverrides.jvm；cp-ansible 用各元件的 *_custom_java_args。
    • 是否已遭利用：公告寫 Confluent Cloud 已緩解，未在自家基礎設施看到利用嘗試；沒有提到客戶環境的利用情形。
  • 對我們的影響：用 Confluent Platform 容器映像（含 CFK 部署）的客戶目前沒有修補版映像可換，只能先在各元件加上 -XX:-UseBASE64Intrinsics 後重啟；還在 Java 8 的元件不要加，會無法啟動。用套件或壓縮檔安裝、自備 Java 的環境，把 JDK 升到修正版即可。
