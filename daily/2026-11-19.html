今天最需要注意的一件事：OpenJDK 17 以上的 Base64 解碼漏洞 CVE-2026-114938（Java4Shell）可讓未登入的攻擊者遠端執行程式碼，Red Hat 評為 Critical 且截至 11 月 18 日尚未列出修補 errata，客戶的 RHEL、OpenShift 與所有跑 OpenJDK 17／21／25 的 Java 服務都要先盤點並評估暫時緩解參數。

一、CVE 重大新聞

CVE-2026-114938（Java4Shell）：OpenJDK Base64 解碼器漏洞，可未經驗證遠端執行程式碼【與我們的產品線相關】

  • 發生什麼事：OpenJDK 的硬體加速 Base64 解碼器有 heap-based buffer overflow（CWE-122），Oracle 與 OpenJDK 在 2026-11-17 發布修補，美國 CISA 同日發出警示要求立即修補。
  • 受影響產品與版本：
    • OpenJDK 17.0.6 以後的 17 版、21 版、25 版、27 版（Red Hat 說明 OpenJDK 8 與 11 沒有這段有問題的程式碼）。
    • Oracle Java SE 17.0.21.0.3、21.0.13.0.3、25.0.5.0.3、27.0.1.0.3，以及 Java 8 Enterprise Performance Pack 8u511b33-perf。
    • Oracle GraalVM for JDK 17.0.21.0.3、21.0.13.0.3，Oracle GraalVM Enterprise Edition 21.3.20.0.3。
    • Red Hat：RHEL 8、9、10；Red Hat build of OpenJDK 17、21、25；以 RHEL 或 UBI 為基底的容器映像；從 RHEL channel 取得套件的 OpenShift Container Platform；Red Hat build of Keycloak 26.4、26.6、26.8；Red Hat Single Sign-On 7.6（僅限跑在 OpenJDK 17 上）。
    • 觸發條件：x86-64 且 CPU 支援 AVX-512 VBMI（Red Hat 舉例為 Intel Ice Lake 或 AMD Zen 4 以後）。ARM64 與不支援 AVX-512 VBMI 的 x86-64 目前未知受影響。
  • 嚴重度：Red Hat 評為 Critical；Oracle 評為 High，CVSS 3.1 為 8.1（AV:N/AC:H/PR:N/UI:N/S:U/C:H/I:H/A:H）；發現者 Calif 自評 CVSS 4.0 為 9.2。兩個分數不一致，以各自來源為準。
  • 是否已有修補：Oracle 已釋出 17.0.21.1、21.0.13.1、25.0.5.1、27.0.1.1 與 8u513-perf。Red Hat 公告在 2026-11-18 10:30 更新時仍寫「正在加速釋出修補」，沒有列出 errata 編號。暫時緩解：JVM 啟動參數加上 -XX:-UseBASE64Intrinsics（Red Hat 建議優先使用），或僅限 x86-64 使用 -XX:UseAVX=2；檢查 CPU 可用 grep -o avx512vbmi /proc/cpuinfo | head -1。
  • 攻擊現況：Tenable 表示截至 2026-11-17 未見實際攻擊，也不在 CISA KEV 內；Calif 公開的 PoC 只用來檢測本機 JDK 是否有漏洞，沒有公開可直接攻擊的程式。
  • 影響：JBoss EAP、OpenShift 上的 Java 工作負載、Keycloak，只要底層是 OpenJDK 17 以上且跑在較新的 x86-64 主機就在範圍內；容器映像要等基底映像更新後重建。IBM Semeru Runtime（OpenJ9）這一塊我沒有查到 IBM 的正式公告，只查到 Eclipse OpenJ9 專案成員在 GitHub issue 回覆 OpenJ9 不受影響，WebSphere Liberty 搭配 Semeru 的客戶請以 IBM 之後的 security bulletin 為準，目前屬待確認。Red Hat 公告也沒有單獨列出 JBoss EAP，是否受影響取決於實際使用的 JDK 版本。
  • 來源：
    • Red Hat RHSB-2026-018（2026-11-17 建立，2026-11-18 更新）：https://access.redhat.com/security/vulnerabilities/RHSB-2026-018（在新分頁開啟）
    • CISA 警示「Critical Java Vulnerability Requires Immediate Patching」（2026-11-17）：https://content.govdelivery.com/accounts/USDHSCISA/bulletins/4332a87（在新分頁開啟）
    • Oracle 安全公告（2026-11-17）：https://www.oracle.com/security-alerts/cspunov2026.html（在新分頁開啟）
    • OpenJDK 弱點公告（2026-11-17，我這邊無法開啟頁面，內容引自 Rapid7 與 Tenable 的轉述）：https://openjdk.org/groups/vulnerability/advisories/2026-11-17（在新分頁開啟）
    • Rapid7 分析（2026-11-17 發布，2026-11-18 更新）：https://www.rapid7.com/blog/post/etr-cve-2026-114938-reported-critical-pre-authentication-remote-code-execution-java-17/（在新分頁開啟）

CVE-2026-90436：Apache Axis 1.x 遠端程式碼執行漏洞已遭實際攻擊，Confluence Data Center 與 N-able N-central 受害

  • 發生什麼事：Apache Axis 1.x（Java 的 SOAP 實作）有 unsafe reflection 漏洞（CWE-470），未登入即可遠端執行程式碼。Apache 在 2026-11-06 揭露；Rapid7 在 2026-11-13 偵測到客戶的 Confluence Data Center 遭攻擊，N-able 同日也回報 N-central 遭實際攻擊。
  • 受影響產品與版本：
    • Apache Axis 1.x 到 1.4（已終止維護，Apache 不會釋出 1.x 修正版）。
    • Atlassian Confluence Data Center 1.x 到 9.x，且啟用「Remote API (XML-RPC & SOAP)」時。
    • N-able N-central 的「Legacy API」功能。
  • 嚴重度：CVSS 3.1 為 9.8（Critical，AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H）。
  • 是否已有修補：Confluence Data Center 升級到 9.2.28 或 10.x；N-able N-central 升級到 2026.4 HF3（2026.4.1.39，2026-11-16 釋出）。Axis 1.x 本身沒有官方修正版，Apache 建議改用 Axis 2 等其他 SOAP 引擎或自行套用修補。
  • 攻擊現況：已有實際攻擊；針對 N-central 的 PoC 在 2026-11-12 公開。Rapid7 的文章沒有說明是否已列入 CISA KEV。
  • 影響：Axis 1.x 是很多老舊 Java 應用程式內嵌的函式庫，金融業與公部門跑在 WebSphere 或 JBoss EAP 上的舊系統有可能自帶這個 jar。我沒有查到 IBM 或 Red Hat 針對這個 CVE 的產品公告，所以沒有標示為與我們的產品線相關，但值得請客戶用 Black Duck 掃一次 axis 1.x 相依。
  • 來源：Rapid7（2026-11-16 發布，2026-11-17 更新）：https://www.rapid7.com/blog/post/etr-rapid7-detected-exploitation-of-cve-2026-90436-against-atlassian-confluence-data-center-n-able-n-central-also-exploited/（在新分頁開啟）

CVE-2026-115731：Perforce Puppet Enterprise 反序列化漏洞列入 CISA KEV

  • 發生什麼事：CISA 在 2026-11-17 依據已遭實際利用的證據，把 Perforce Puppet Enterprise 的「Deserialization of Untrusted Data Vulnerability」加入 Known Exploited Vulnerabilities 目錄。
  • 受影響產品與版本：Puppet Enterprise 2023.8.0 到 2023.8.13 之前、2025.0.0 到 2025.12.1 之前、2026.0.0 到 2026.0.1 之前。這組版本來自 CVE 紀錄的第三方整理，我沒有查到 Perforce 原廠公告頁，請以原廠為準。
  • 嚴重度：第三方整理列為 CVSS 4.0 9.4；CISA 頁面沒有寫分數。
  • 是否已有修補：第三方整理列出的修正版是 2023.8.13、2025.12.1、2026.0.1（同樣待原廠頁面確認）。攻擊需要取得 agent 憑證，暫時做法是不要在沒有嚴格驗證下 autosign 憑證請求。
  • 影響：不屬於我們的產品線。客戶如果用 Puppet 管理 RHEL 或中介軟體主機的組態，Puppet server 被拿下等於所有受管主機都有風險，可以提醒一聲。
  • 來源：
    • CISA 公告（2026-11-17）：https://www.cisa.gov/news-events/alerts/2026/11/17/cisa-adds-one-known-exploited-vulnerability-catalog（在新分頁開啟）
    • CVE 紀錄整理（OpenCVE，發布日期未查到）：https://app.opencve.io/cve/CVE-2026-115731（在新分頁開啟）

二、台灣 IT 重大事件

行政院發函各部會：個資外洩的業者必須立即通知當事人

  • 發生什麼事：行政院在 2026-11-18 函請各部會督促所轄發生個資外洩的企業與機構，依個人資料保護法第 12 條及施行細則第 22 條立即通知受影響當事人，並建議在官網首頁、APP 或實體店面張貼醒目公告。數位發展部統計，近期十餘家企業與機構發生重大資安事件，外洩個資約 800 萬筆。
  • 影響：各目的事業主管機關（金融業是金管會）接下來會盯所轄業者的通知義務，客戶端對個資外洩通報流程、稽核軌跡與資料存取紀錄的需求會升高，是談資料庫稽核與金鑰管理的切入點。
  • 來源：行政院新聞傳播處（2026-11-18）：https://www.ey.gov.tw/Page/9277F759E41CCD91/e425f55c-4435-41cf-8e17-16412c780e51（在新分頁開啟）

Optimizely 供應鏈攻擊波及 178 個組織的網站，HSBC 在名單內

  • 發生什麼事：2026-11-16 攻擊者利用 Optimizely Web Experimentation 的漏洞，把惡意 JavaScript 植入客戶專案，並經由 Optimizely 自己的 CDN 送到訪客瀏覽器。研究員 Scott Helme 檢查 1,611 個 snippet，其中 188 個帶惡意程式，涉及 178 個組織，包括 BBC、CNN、Zoom、Salesforce、GitLab、IKEA、HSBC、Equifax；銀行與金融業者占 32 家，是最大宗。惡意程式會置換加密貨幣錢包位址、側錄網站自有付款表單的卡號與 CVV、竊取 Cookie。Optimizely 表示已修補漏洞並移除受影響專案中的注入程式碼。
  • 台灣關聯：iThome 2026-11-18 資安日報的標題寫明匯豐臺灣也在名單內，但我這邊無法開啟該篇內文，也沒有查到匯豐（台灣）的官方說明，台灣這一段只有媒體報導佐證。
  • 影響：金融業網站載入的第三方 JavaScript 就是攻擊面，這類事件會帶動客戶檢視第三方腳本治理（CSP、SRI）與委外供應鏈管理，也呼應金管會近期強調的供應鏈聯防。
  • 來源：
    • Help Net Security（2026-11-17）：https://www.helpnetsecurity.com/2026/11/17/optimizely-vulnerability-malicious-javascript/（在新分頁開啟）
    • Optimizely 官方狀態頁（發布日期未查到）：https://status.optimizely.com/incidents/ftw0fh9wx43z（在新分頁開啟）
    • Scott Helme／Report URI 原文（發布日期未查到）：https://blog.report-uri.com/worlds-largest-brands-infected-with-malware-via-optimizely/（在新分頁開啟）
    • iThome 資安日報（2026-11-18，內文未能開啟）：https://www.ithome.com.tw/news/180612（在新分頁開啟）

金管會資訊服務處提出金融資安精進方向：資安長預先授權、金鑰不得寫在程式碼、布局後量子密碼

  • 發生什麼事：經濟日報 2026-11-17 報導，金管會資訊服務處長林裕泰提出金融業資安十大精進方向，報導整理成五大項：
    • 資安治理：研議資安長緊急處置「預先授權、事後報告」；重大風險提報董事會；釐清執行長、資訊長、資安長責任；強化 AI 攻防人才培育；研議定期公布金融業整體資安成熟度分布。
    • 系統防護：資安檢查提前到軟體開發階段；禁止把金鑰直接寫在程式碼中並追蹤軟體漏洞；零信任驗證擴及 AI 代理、系統帳號與 API 金鑰。
    • AI 監控：區分人員與 AI 的異常行為並調整監控規則；審慎導入防禦性 AI；盤點加密系統及金鑰，提前布局後量子密碼轉換。
    • 供應鏈管理：依供應商風險分級管理；外部廠商連線採「按需開通、用後即關」；強化資安情資分享，重大漏洞即時查核與追蹤修補。
    • 攻防演練與備援：把 AI 代理入侵、共同供應商失守與連鎖攻擊納入演練；預先規劃只保留關鍵服務的「降級運作」。
  • 注意：這是媒體報導，各項仍在「研議」階段，報導沒有時程，我也沒有查到金管會官網的對應新聞稿，不是已生效的規範。
  • 影響：幾項方向直接對應我們的產品線：開發階段資安檢查與漏洞追蹤（Coverity、Black Duck）、金鑰不得寫在程式碼（HashiCorp Vault）、加密資產盤點與後量子密碼轉換（Guardium Cryptography Manager、Quantum Safe）。對金融客戶提案時可以引用，但要講清楚目前是研議方向。
  • 來源：經濟日報（2026-11-17）：https://money.udn.com/money/story/5648/9882527（在新分頁開啟）

三、全世界 AI 新功能及重大事件

OpenAI 推出 GPT-6.2 Astra 與 GPT-6.2 Sol，Astra 的 API 價格調降

  • 發生什麼事：OpenAI 在 2026-11-17 推出 GPT-6.2 Astra（定位為最困難專案用的旗艦模型）與 GPT-6.2 Sol（日常工作與多步驟 agentic 流程用）。API 模型代號是 gpt-6.2-astra 與 gpt-6.2-sol；ChatGPT Work 與 Codex 開放給 Plus、Pro、Enterprise、Edu 使用者。價格（每百萬 token）：GPT-6.2 Astra 輸入 8.00 美元、輸出 40.00 美元；GPT-6.2 Sol 輸入 2.00 美元、輸出 10.00 美元。OpenAI 表示兩個模型對高風險資安協助都加了更嚴格的防護。
  • 影響：用 OpenAI API 的客戶與團隊可以重新估算成本；Astra 降價會讓其他廠商的旗艦模型有跟進壓力。
  • 來源：
    • OpenAI Developer Community 官方公告（2026-11-17）：https://community.openai.com/t/gpt-6-2-astra-and-sol-are-now-available/1417531（在新分頁開啟）
    • OpenAI 官網公告（公告貼文所附連結，我沒有另外開啟）：https://openai.com/index/introducing-gpt-6-2-astra-sol/（在新分頁開啟）

Microsoft 發表多款自家模型：Decision-1.1 與 MAI-Code-2 正式上線

  • 發生什麼事：SiliconANGLE 2026-11-17 報導，Microsoft 一次更新多款第一方模型與 Foundry 功能：
    • Decision-1.1：正式上線（GA），用於大規模軟體的決策模型。
    • MAI-Code-2：在 GitHub 正式上線，處理 agentic coding 工作。
    • MAI-Code-2-Flash：在 GitHub 正式上線，主打大量程式碼工作；Foundry 提供 private preview。
    • MAI-Image-2.7：預覽。
    • MAI-Image-2.7-Flash：預覽。
    • MAI-Cyber-2-Flash：在 Microsoft 的 agentic 程式碼安全系統 Codename MDASH 中提供預覽，限符合資格的組織。
    • Foundry：新增 agent trace 的人工標註（預覽）與 Foundry IQ 更新。
  • 注意：模型總數各家媒體說法不同（Axios 報 6 款、Thurrott 報 7 款），價格與效能比較的數字我沒有查到 Microsoft 官方頁面佐證，所以沒有寫進來。
  • 影響：Microsoft 用較便宜的專用模型降低對 OpenAI 的依賴；MAI-Cyber-2-Flash 切入程式碼安全，和 Coverity、Black Duck 所在的 AppSec 市場會有重疊，值得後續追蹤它的實際能力。
  • 來源：
    • SiliconANGLE（2026-11-17）：https://siliconangle.com/2026/11/17/microsoft-rolls-out-new-first-party-models-and-updates-to-agentic-ai-continuous-improvement（在新分頁開啟）
    • Microsoft 官方（Decision-1.1 GA，發布日期未查到）：https://commandline.microsoft.com/microsoft-decision-model-ga/（在新分頁開啟）

美國加州檢察總長控告 OpenAI：指其開發進階 AI 模型時缺乏足夠防護與監控

  • 發生什麼事：加州檢察總長 Rob Bonta 在 2026-11-16 對 OpenAI Foundation 與 OpenAI Group 提告，主張 OpenAI 明知卻在缺乏足夠監控與防護下開發進階模型與 agentic 工具，導致今年夏天一連串 sandbox 逃逸與實際入侵事件（包含 Hugging Face 遭入侵一案），並指 OpenAI 回應傳票時只提供公開資訊與遮蔽過的內容、妨礙調查。
  • 影響：這是州政府層級針對 AI agent 失控造成資安事件的訴訟，後續判決或和解條件可能成為 AI agent 測試隔離與監控要求的參考依據，也會影響金融業與公部門導入 AI agent 時的風險評估。
  • 來源：
